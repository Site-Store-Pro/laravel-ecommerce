1. Overview

The plugin system is a fully dynamic, database-driven architecture that enables display elements (Swiper slideshows, galleries) and shipping providers (FedEx) to be registered, configured, and embedded into any CMS page or product description without code changes.

Key concepts:

  • Plugins auto-discovered — built-in classes in app/Plugins/ OR drop-in folders in root /plugins/ directory
  • All settings stored in DB, managed via Admin Panel at /admin/plugins
  • Display plugins embedded using shortcodes: [plugin:slug] or [plugin:slug param=value]
  • Shipping plugins invoked programmatically via PluginManager singleton
  • No artisan commands needed to activate a plugin — toggling active in the admin is sufficient

4. How Shortcodes Work

The ShortcodeProcessor uses preg_replace_callback to scan content for [plugin:slug] or [plugin:slug key=value] patterns.

Flow:

  1. ContentParserService (Blade renderer) pipes content through ShortcodeProcessor::process()
  2. Each match: PluginManager looks up the registered DisplayPlugin by slug
  3. plugin->render(array $params, Plugin $plugin) is called
  4. Returned HTML replaces the shortcode inline

Example shortcodes:

[plugin:slideshow-2026]
[plugin:slideshow-2026 id=3]
[plugin:slideshow-2026 id=2 nav=off paging=off]

5. Built-in Plugins

Slideshow Plugin (type: display)

  • Shortcode: [plugin:slideshow-2026]
  • File: app/Plugins/Display/SlideshowPlugin.php
  • View: resources/views/plugins/display/slideshow.blade.php
  • Engine: Swiper.js (CDN, @once directive prevents conflicts)
  • Parameters: id (slideshow ID), nav (on/off), paging (on/off), autoplay (on/off), speed (ms)
  • Admin Settings: Live CSS (editable dark code editor), Default CSS (read-only reference)
  • Slide data managed at: /admin/slideshows

FedEx Shipping Plugin (type: shipping)

  • Filename slug: fedex_api_2026
  • File: app/Plugins/Shipping/FedExPlugin.php
  • API: FedEx REST API v1 with OAuth2 (NOT legacy SOAP)
  • Required credentials: Account Number, Client ID, Client Secret
  • Toggle per-service: Ground, Ground Home Delivery, Express Saver, 2-Day Air, 2-Day Air AM, Priority Overnight, Standard Overnight, First Overnight, International Priority, International Economy, International First, 1/2/3-Day Freight
  • Markup/Markdown: numeric adjustment to all returned rates

7. Creating a New Built-in Plugin

Step 1 — Create the PHP class in app/Plugins/Display/ or app/Plugins/Shipping/

Display plugin example:

<?php
namespace App\Plugins\Display;
use App\Models\Plugin;
use App\Plugins\Contracts\DisplayPlugin;

class MyPlugin implements DisplayPlugin
{
    public function slug(): string { return 'my-plugin'; }
    public function name(): string { return 'My Custom Plugin'; }

    public function render(array $params, Plugin $plugin): string
    {
        $setting = $plugin->getSetting('my_setting', 'default');
        return view('plugins.display.my-plugin', compact('params', 'setting'))->render();
    }
}

Shipping plugin returns array of rate options:

return [
    ['label' => 'Standard Rate', 'rate' => 12.50, 'days' => 3, 'code' => 'MY_CODE'],
];

Step 2 — Register in PluginServiceProvider boot() method:

$manager->register(\App\Plugins\Display\MyPlugin::class);

Step 3 — Add DB record + options to PluginSeeder.php then run:

php artisan db:seed --class=PluginSeeder

8. Creating a Drop-in External Plugin

Drop-in plugins live in the root /plugins/ directory and are auto-discovered on boot.

Folder structure:

plugins/
  my-custom-plugin/
    plugin.json
    MyCustomPlugin.php

plugin.json format:

{
  "class": "MyCustomPlugin",
  "name": "My Custom Plugin",
  "version": "1.0",
  "type": "display",
  "shortcode": "my-custom",
  "description": "A drop-in custom plugin",
  "author": "Your Name",
  "options": [
    {
      "field_name": "api_key",
      "field_label": "API Key",
      "field_type": "input",
      "field_required": "yes",
      "sort_order": 10,
      "field_default_value": ""
    }
  ]
}

Discovery flow in PluginManager::discoverExternalPlugins():

  1. Scans /plugins/*/plugin.json
  2. require_once's the PHP class file
  3. Calls syncExternalPlugin() — upserts DB record + options
  4. Registers the class instance

9. Accessing Plugin Settings in Code

use App\Models\Plugin;

$plugin = Plugin::where('shortcode', 'slideshow-2026')->first();

// All settings as key => value array
$settings = $plugin->getSettings();

// Single setting with fallback
$css = $plugin->getSetting('live_css', '');

// Save settings (upserts into plugin_settings)
$plugin->saveSettings(['live_css' => '.wrapper { width: 100%; }']);

// Get options schema (ordered by sort_order)
$schema = $plugin->getOptionsSchema();

// Check active plugins by type
$displayPlugins = Plugin::scopeActive()->scopeOfType('display')->get();

10. Deployment Checklist

After uploading all files to a new server:

php artisan migrate                      # Creates the 3 plugin tables
php artisan db:seed --class=PluginSeeder # Seeds Slideshow + FedEx with all options
php artisan optimize:clear               # Clears caches so PluginServiceProvider loads

No other plugin-specific artisan commands are required. PluginServiceProvider is auto-loaded from bootstrap/providers.php on every request.

Routes added:

  • GET /admin/plugins → AdminPlugins Livewire component
  • GET /admin/plugins/list-display → PluginApiController::listDisplay() JSON

Sidebar nav link added to: resources/views/layouts/cms-sidebar.blade.php
